# PResolver

PResolver es una iniciativa dedicada a comprender cómo abordar, resolver, continuar y revisar problemas preservando la continuidad del conocimiento relevante. Esta es su superficie de trabajo propia, **inicializada de forma mínima**; no representa aún la adopción o consolidación de productos, métodos, contratos o implementaciones.

## Fuente conceptual vigente

Mientras no exista una transferencia y adopción explícitas de definiciones, la entrada canónica es [vslices/ideas/proyectos/p-resolver/README.md](https://github.com/vslices/ideas/blob/main/proyectos/p-resolver/README.md). El material de ese directorio conserva la genealogía, las hipótesis, los límites y las definiciones pertinentes. Este repositorio no sustituye retroactivamente esa autoridad ni presume que todo lo allí propuesto esté validado.

## Uso para el caso supervisado S

La investigación XFR-STU-001 prepara una trayectoria supervisada de VSlices → PResolver → TDidacta, con KCollectiva como conjunto candidato de reglas para examinar transferencias.

- El trabajo conductor se realiza en [tdidacta/platform](https://github.com/tdidacta/platform).
- Las **abstracciones candidatas y sus revisiones** se prepararán en una rama de este repositorio, sin alterar `main`.
- Las **proyecciones candidatas** se prepararán en una rama de [the-alive-lab/tdidacta](https://github.com/the-alive-lab/tdidacta).
- Cada propuesta debe conservar fuente, responsabilidades, garantías, pérdidas, contraejemplos, alternativas rechazadas, decisiones de supervisión y enlaces a commits.
- No hay obligación de reproducir Method, Design, Docs Standard y Framework ni de convertir una pregunta útil en estructura nueva.
- Una rama, PR o documentación exploratoria no significa aprobación o promoción conceptual.

Protocolo de investigación: [XFR-STU-001, Caso S](https://github.com/vslices/research-space/blob/main/lines/cross-flavor-resolution/studies/stu-001-transferencia-tdidacta/12-caso-s-supervisado-presolver-kcollectiva.md).

## Reutilización canónica para postulaciones y financiamiento

Uno de los objetivos operativos de estas definiciones canónicas es proporcionar una base de conocimiento **suficiente, vigente y trazable** para derivar abstracts y postulaciones a financiamiento sin reconstruir reiteradamente la identidad, el problema que se aborda, el propósito, las responsabilidades, los mecanismos, el estado y la evidencia del proyecto.

Cada postulación es una **proyección contextual** de las definiciones y antecedentes pertinentes: debe adaptarse al método, público, requisitos, límites de extensión y criterios de evaluación de su convocatoria. Ni las restricciones de un formulario redefinen el proyecto, ni una postulación presentada adquiere por ello autoridad canónica.

La fuente debe preservar las distinciones materiales con redacción concisa, sin imponer límites arbitrarios de extensión ni convertir el README en un formulario. Cuando corresponda, se enlazarán documentos específicos, historia, decisiones, evidencia, hipótesis y realizaciones, diferenciando su estado y autoridad. Las capacidades previstas, resultados aún no demostrados, alianzas no confirmadas y compromisos futuros nunca deben presentarse como hechos establecidos. Antes de presentar una postulación, deben verificarse los datos actuales y obtenerse la aprobación correspondiente.

**Criterio de suficiencia:** un autor debería poder reconstruir una propuesta fiel al proyecto consultando esta superficie y sus referencias explícitas, sin rehacer desde cero la mayor parte de la investigación contextual; esto es un objetivo documental, no una garantía de que toda convocatoria pueda completarse sin trabajo adicional.
